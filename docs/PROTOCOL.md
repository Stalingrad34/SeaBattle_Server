# SeaBattle: сеть

## Состояние

Источник структуры — серверный `src/rooms/schema/MatchState.ts`: Schema и @type, как в SlapBattles.
Из папки Server выполните `npm run export`, чтобы обновить C# в `Assets/Game/Scripts/Multiplayer/Generated`. Генерируемые файлы вручную не редактируются.

Colyseus автоматически передаёт начальное состояние и изменения через OnStateChange.
MatchState содержит фазу, очередь, revision, turnId, deadlineMs и правила.
StateView передаёт каждому игроку только его PlayerState: собственные корабли и результаты выстрелов.
Клетки чужого корабля раскрываются только при его потоплении.

## Сообщения

Клиент отправляет `room.Send("fire", command)`, сервер принимает через `onMessage("fire", ...)`.
Ответ — `client.send("commandResult", result)`. Объекты сериализует сам Colyseus.

- FireCommand: commandId, turnId, x, y.
- CommandResult: commandId, turnId, revision, status (applied/rejected), reason.
- error: строка invalid_request при неверном формате команды.
- serverTime: запрос — целочисленный requestId, ответ — { requestId, serverTimeMs }. serverTimeMs — монотонное время сервера в миллисекундах. Клиент принимает ответ только на текущий запрос, учитывает половину времени запроса для таймера. Сообщение также служит heartbeat.

Игрок определяется по client.sessionId. Передавать playerId, connectionId или matchId в команде не требуется.
commandId — 1–128 латинских букв, цифр, дефисов или подчёркиваний; turnId — положительное целое; координаты — с нуля.

Точный повтор команды возвращает прежний результат (applied или rejected) без повторного выстрела.
Изменённая команда с тем же ID отклоняется с command_conflict.
Другие причины отказа: unauthorized, match_not_started, match_finished, wrong_turn, turn_expired, out_of_bounds, already_shot.
Результаты хранятся до удаления партии, максимум 2048 команд на игрока; новые команды сверх лимита отклоняются с command_limit. Кеш уже известных ID при этом продолжает работать.

Результат и патч состояния могут прийти в разное время: revision ответа связывает их.
deadlineMs использует монотонное серверное время, не UTC.

## Текущее поведение

Есть одна комната battle на двух игроков. Второй игрок запускает матч; первый ход выбирается случайно.
Сервер управляет расстановкой, выстрелами, таймером и победой. Добровольный выход из начавшейся партии означает поражение.
Неожиданный обрыв вызывает allowReconnection(client, ReconnectGraceSeconds). Клиент использует штатный Reconnect с сохранённым reconnectionToken; sessionId и игровое состояние сохраняются. Новый токен записывается после каждого успешного соединения. Сервер заново назначает приватный StateView. Истечение срока означает поражение или освобождение места в ожидающей комнате. Таймер хода не останавливается.

Клиент сохраняет pending-команду перед отправкой и повторяет её после восстановления или задержки ответа. Applied подтверждается только вместе со Schema нужной revision; rejected завершает ожидание сразу. Новые команды запрещены, пока исход предыдущей неизвестен. Колбэки проверяют текущую комнату и поколение соединения. Новый полный снимок той же revision заменяет объект старого соединения; более старые ревизии отбрасываются.

Один экземпляр Unity — один игрок. Запуск приложения показывает попап комнат и автоматически пытается восстановить сохранённую сессию, если она есть.
Кнопки вызывают Create("battle", { roomName, gameConfig: { BoardSize, ShipLengths, TurnDurationSeconds } }) и JoinById(roomName). Имя из 8 латинских букв или цифр с учётом регистра становится roomId; дубликаты в пределах процесса запрещены.
Параметры создателя проходят серверную проверку; неверные отклоняются с invalid_game_config. При отсутствии gameConfig используются серверные значения по умолчанию. Присоединение и переподключение не меняют правила. ReconnectGraceSeconds остаётся серверной настройкой. Принятые размер поля, флот и время хода передаются обоим клиентам через MatchState.

## Эмуляция плохой сети

NetworkSimulator обрабатывает исходящие fire/serverTime и входящие commandResult/serverTime/error, а также независимые снимки приватной Schema. Настраиваются задержка ± разброс, потери, дубликаты и seed. При тихом разрыве сообщения отбрасываются без события транспортного отключения. После восстановления действуют прежние проверки поколения соединения и revision.

Нельзя терять бинарные дельты Schema перед декодером: следующие дельты зависят от предыдущих. Поэтому SDK поддерживает своё состояние, а игра получает глубокие копии через эмулятор; CurrentState также возвращает только доставленный снимок. Heartbeat создаёт повторную возможность доставить текущий снимок, в том числе после потерянного последнего обновления партии.
