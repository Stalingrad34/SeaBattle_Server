# SeaBattle Server

Отдельный репозиторий в папке Server клиентского проекта. Node.js 22+.

```powershell
npm ci
npm start
```

Сервер запускается вручную, Unity не управляет процессом. Для локального клиента адрес ws://127.0.0.1:2567; порт меняется через PORT. npm start запускает сервер с перезапуском при изменениях. Для запуска собранной версии: npm run build, затем npm run start:prod. npm test — сборка и тесты.

## Игровая логика (этап 3)

Комната `battle` рассчитана на двух игроков. Первый ждёт, при входе второго сервер начинает партию и случайно выбирает первого ходящего. Create("battle", { roomName }) создаёт комнату с указанным roomId, JoinById(roomName) входит в неё. Имя — ровно 8 латинских букв или цифр; регистр учитывается. Занятые имена отклоняются. Реестр имён рассчитан на один процесс.

- `game/BattleGame.ts`: авторитетные правила поверх Schema — очередность, miss/hit/sunk, победа, ревизии и таймер.
- `game/FleetPlacement.ts`: случайные прямые корабли без пересечений, с откатом неудачной расстановки. Соприкосновение запрещено, включая диагонали; каждый корабль занимает непрерывную горизонтальную или вертикальную линию. Поиск ограничен 100000 вариантами, чтобы чрезмерно плотная конфигурация не зависала.
- `rooms/BattleRoom.ts`: связь Colyseus с правилами, авторизация по транспортной сессии, проверка сообщений и приватные StateView.
- `config/GameConfig.ts`: загрузка серверных значений по умолчанию и валидация параметров. Создатель передаёт gameConfig с BoardSize, ShipLengths и TurnDurationSeconds. После проверки они становятся правилами новой комнаты; настройки присоединившегося игрока игнорируются. Без gameConfig используется config/game.json. ReconnectGraceSeconds всегда берётся из серверного файла.

Правила по умолчанию: 6×6, корабли 3/2/2/1, ход 15 секунд. Любой допустимый выстрел передаёт очередь, включая попадание и потопление. Повтор в ту же клетку, выстрел вне поля, чужой ход и старый turnId отклоняются без расходования текущего хода.

Сервер проверяет время каждые 100 мс и непосредственно перед выстрелом. На границе deadline выстрел уже просрочен. При задержке самого процесса пропускается один ход и следующему игроку даётся полное время; каскада мгновенных пропусков нет. Время — монотонные миллисекунды performance.now(), не UTC.

Результаты commandId хранятся до уничтожения матча: точный повтор возвращает прежний результат и не изменяет состояние. Повтор ID с другим ходом или координатами отклоняется. Подробности восстановления и ограничения кеша описаны ниже.

Добровольный выход до начала освобождает место, после начала — поражение вышедшему. Начавшаяся комната остаётся закрытой для новых игроков. Состояние finished больше не меняется таймером. Неожиданный обрыв оставляет время на переподключение; сохранения матчей после перезапуска сервера нет.

## Схемы и протокол

`src/rooms/schema/MatchState.ts` — источник Schema/@type. `npm run export` генерирует C# в `../Assets/Game/Scripts/Multiplayer/Generated`. StateView передаёт игроку только его PlayerState с собственными кораблями и результатами выстрелов. sunkCells раскрывает клетки только потопленного корабля. Корабли соперника не передаются даже после завершения.

Команды описаны в src/protocol/messages.ts. Клиент отправляет объект fire, сервер отвечает объектом commandResult. Сериализацию выполняет Colyseus. Подробности — [docs/PROTOCOL.md](docs/PROTOCOL.md).

Запуск повторяет подход SlapBattles: index.ts вызывает listen(appConfig), app.config.ts регистрирует BattleRoom.

## Проверка

`npm test`: 15 тестов. Правила проверяются с управляемыми часами и seed, включая 200 расстановок, дедлайн, двойной клик, повторы, попадание/промах/потопление, победу и выход. Интеграционные тесты проверяют полную партию и переподключение двух независимых клиентов. Временные серверы останавливаются после тестов. Отдельный тест проверяет приватность полной Schema и вложенных обновлений.

## Восстановление связи (этап 5)

При неожиданном обрыве allowReconnection сохраняет игрока на ReconnectGraceSeconds (120 секунд по умолчанию). Таймер партии продолжается. При возврате сохраняются sessionId, корабли, выстрелы и кеш исходов; клиент получает полную приватную Schema. После истечения срока игрок проигрывает, а до начала партии освобождает место. Добровольный выход завершает участие сразу.

Кешируются результаты принятых и отклонённых fire-команд: повтор того же commandId и содержимого возвращает прежний ответ. Лимит — 2048 команд на игрока; известные ID обслуживаются и после достижения лимита. serverTime возвращает { requestId, serverTimeMs } и используется клиентом как heartbeat. Матчи остаются только в памяти процесса.

Проверены 15 тестов, включая реальное переподключение с потерянным ответом, приватные sunkCells после восстановления и поражение по истечении срока. Подробности — docs/PROTOCOL.md.

Этап 7: unreliable-network.test.mjs проводит три полные партии с seed 7/42/2026, потерями 25%, дубликатами 40% и задержками. Весь приватный снимок каждого клиента сравнивается с сервером. reconnection.test.mjs также проверяет одновременный разрыв обоих игроков и сохранение истории команд.
