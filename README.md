# SeaBattle Server

Отдельный репозиторий в папке Server клиентского проекта. Node.js 22+.

```powershell
npm ci
npm start
```

Сервер запускается вручную, Unity не управляет процессом. Для локального клиента адрес ws://127.0.0.1:2567; порт меняется через PORT. npm start запускает сервер с перезапуском при изменениях. Для запуска собранной версии: npm run build, затем npm run start:prod. npm test — сборка и тесты.

## Игровая логика (этап 3)

Комната `battle` рассчитана на двух игроков. Первый ждёт, при входе второго сервер начинает партию и случайно выбирает первого ходящего. Пока не реализован пользовательский поиск/создание по 8-символьному имени; интеграционный тест использует стандартные Colyseus create/joinById. Кнопки Unity остаются без сетевых обработчиков.

- `game/BattleGame.ts`: авторитетные правила поверх Schema — очередность, miss/hit/sunk, победа, ревизии и таймер.
- `game/FleetPlacement.ts`: случайные прямые корабли без пересечений, с откатом неудачной расстановки. Соприкосновение разрешено, поскольку ТЗ его не запрещает. Поиск ограничен 100000 вариантами, чтобы чрезмерно плотная конфигурация не зависала.
- `rooms/BattleRoom.ts`: связь Colyseus с правилами, авторизация по транспортной сессии, проверка сообщений и приватные StateView.
- `config/GameConfig.ts`: загрузка и валидация config/game.json, экспортированного из Unity GameConfig.asset. Файл проверяется при запуске и читается для каждой новой комнаты; существующие матчи сохраняют свои правила. Параметры клиента не меняют правила.

Правила по умолчанию: 6×6, корабли 3/2/2/1, ход 15 секунд. Любой допустимый выстрел передаёт очередь, включая попадание и потопление. Повтор в ту же клетку, выстрел вне поля, чужой ход и старый turnId отклоняются без расходования текущего хода.

Сервер проверяет время каждые 100 мс и непосредственно перед выстрелом. На границе deadline выстрел уже просрочен. При задержке самого процесса пропускается один ход и следующему игроку даётся полное время; каскада мгновенных пропусков нет. Время — монотонные миллисекунды performance.now(), не UTC.

Принятые commandId хранятся до уничтожения матча: точный повтор возвращает прежний результат и не изменяет состояние. Повтор ID с другим ходом или координатами отклоняется. Кеш ограничен числом допустимых выстрелов на поле. Хранение отклонённых команд, sync/resume, восстановление клиента и гарантия доставки исхода остаются этапом 5.

Пока выход до начала освобождает место, после начала — поражение вышедшему. Начавшаяся комната остаётся закрытой для новых игроков. Состояние finished больше не меняется таймером. Переподключения и использование ReconnectGraceSeconds добавляются на этапе 5; сохранения матчей после перезапуска сервера пока нет.

## Схемы и протокол

`src/rooms/schema/MatchState.ts` — источник Schema/@type. `npm run export` генерирует C# в `../Assets/Game/Scripts/Multiplayer/Generated`. StateView передаёт игроку только его PlayerState с собственными кораблями и результатами выстрелов. sunkCells раскрывает клетки только потопленного корабля. Корабли соперника не передаются даже после завершения.

Команды описаны в src/protocol/messages.ts. Клиент отправляет объект fire, сервер отвечает объектом commandResult. Сериализацию выполняет Colyseus. Подробности — [docs/PROTOCOL.md](docs/PROTOCOL.md).

Запуск повторяет подход SlapBattles: index.ts вызывает listen(appConfig), app.config.ts регистрирует BattleRoom.

## Проверка

`npm test`: 9 тестов. Правила проверяются с управляемыми часами и seed, включая 200 расстановок, дедлайн, двойной клик, повторы, попадание/промах/потопление, победу и выход. Интеграционный тест запускает временный сервер и проводит полную партию двух независимых клиентов, проверяя приватные патчи, повторные команды и совпадение результатов. Временный процесс останавливается после теста. Отдельный тест проверяет приватность полной Schema и вложенных обновлений.
